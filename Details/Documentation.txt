## ✅ Problem Statement: Salon Management System

In the current digital era, many salons still rely on traditional methods like phone calls, manual appointment books, or spreadsheets to manage their operations. These outdated systems are inefficient and error-prone, especially as the business grows. A digital solution is needed to manage appointments, services, employees, customers, and payments in a streamlined and user-friendly way.

The **Salon Management System** aims to simplify and automate the day-to-day operations of a salon. The goal is to provide a centralized platform where salon owners, employees, and customers can interact through different access levels.

The system will allow:

* Customers to book and manage appointments online.
* Salon staff to manage bookings, customers, schedules, and services.
* Admins to oversee the entire operation including employee management, service customization, time slot settings, and payment tracking.

---

## 🎯 Objectives

1. **Improve efficiency** of salon operations by digitizing appointment scheduling and staff allocation.
2. **Enhance customer experience** through online booking and automated reminders.
3. **Enable real-time tracking** of appointments, payments, and service history.
4. **Manage staff and resources** efficiently based on service demands.

---

## 👥 User Roles

### 1. **Admin (Superuser/Manager)**

* Full access to the system.
* Can manage staff, services, timings, pricing, and view reports.

### 2. **Staff/Employees (Stylists, Beauticians)**

* View assigned appointments and customer details.
* Update status of appointments (e.g., completed, cancelled).
* Limited access to customer data (for appointments only).

### 3. **Customers**

* Register/login to book appointments.
* View service offerings, select time slots, and receive notifications.
* Manage personal profile and view appointment history.

---

## 🧱 Core Modules & Features

### 1. **Authentication & Authorization**

* Secure login/signup for customers and staff.
* Role-based dashboard access.
* Password reset, email verification.

### 2. **Appointment Booking System**

* Real-time booking calendar.
* Select service, staff (optional), date & time.
* Avoid double booking (availability check).
* Appointment status: Booked, Completed, Cancelled, No-show.

### 3. **Service Management**

* Add/edit/delete services (e.g., haircut, manicure, facial).
* Service duration, pricing, description.
* Service categorization (e.g., Hair, Nails, Skin).

### 4. **Employee/Staff Management**

* Add/edit staff profiles.
* Assign staff to services.
* Availability & working hours management.
* View appointment schedules.

### 5. **Customer Management**

* Customer profiles with appointment history.
* Notes/feedback on each customer (for internal use).
* Loyalty points or history-based tracking (optional feature).

### 6. **Calendar & Scheduling**

* Visual calendar for admin and staff to view appointments.
* Time slot generation based on working hours and service duration.
* Prevent overbooking or overlapping.

### 7. **Payments & Billing**

* Add payment info to each appointment.
* Mark payment status (paid/unpaid).
* Integrate basic payment gateway (optional).
* Generate invoices or receipts (PDF/Email).

### 8. **Notifications & Reminders**

* Email/SMS confirmations after booking.
* Reminder alerts before appointment (24 hrs, 1 hr).
* Admin/staff notified for new bookings or cancellations.

### 9. **Reports & Analytics**

* Daily/weekly/monthly sales report.
* Staff performance (based on services rendered).
* Popular services and time slots.
* Cancelled/no-show appointments tracking.

### 10. **Settings & Configuration**

* Business hours setup.
* Holiday and off-day management.
* Buffer time between appointments.
* General settings for emails, branding, etc.

## 🔧 Technical Architecture

### Backend: Django (Python)

* Models for Users, Appointments, Services, Staff, Payments, etc.
* Django Admin for backend management.
* REST API support (optional if you want a React frontend later).

### Frontend: Django Templates (or optional React/Vue frontend)

* Responsive design (Bootstrap or TailwindCSS).

* **Stripe/PayPal** for online payments.

## ✅ Key Entities (Models)

Here are the core models we'll define:

1. **User** (using Django’s built-in User model, extended with profiles)
2. **CustomerProfile**
3. **StaffProfile**
4. **Service**
5. **Appointment**
6. **TimeSlot** (for managing availability)
7. **Payment**
8. **WorkingHours**
9. **SalonSettings** (optional configuration model)

---

## 🧩 Database Schema Design

---

### 1. **User** (Django’s built-in `auth.User`)

Used for login/authentication. Roles like admin, customer, and staff are determined by related profile models or groups/permissions.

---

### 2. **CustomerProfile**

Extra info for customers.

| Field          | Type                 | Notes               |
| -------------- | -------------------- | ------------------- |
| user           | OneToOneField → User | Extends Django User |
| phone_number   | CharField            |                     |
| address        | TextField            | Optional            |
| loyalty_points | IntegerField         | Optional feature    |
| created_at     | DateTimeField        | Auto-add            |

---

### 3. **StaffProfile**

Used for salon employees like stylists, barbers, beauticians.

| Field         | Type                      | Notes                           |
| ------------- | ------------------------- | ------------------------------- |
| user          | OneToOneField → User      | Extends Django User             |
| role          | CharField                 | e.g. “Hair Stylist”, “Masseuse” |
| phone_number  | CharField                 |                                 |
| services      | ManyToManyField → Service | Services they can perform       |
| working_hours | ForeignKey → WorkingHours | Weekly schedule                 |
| is_active     | BooleanField              | Soft delete option              |
| created_at    | DateTimeField             | Auto-add                        |

---

### 4. **Service**

| Field            | Type          | Notes                     |
| ---------------- | ------------- | ------------------------- |
| name             | CharField     | e.g., “Haircut”           |
| category         | CharField     | e.g., “Hair”, “Skin”      |
| description      | TextField     | Optional                  |
| price            | DecimalField  |                           |
| duration_minutes | IntegerField  | Service length in minutes |
| is_active        | BooleanField  | Show/hide service         |
| created_at       | DateTimeField | Auto-add                  |

---

### 5. **Appointment**

| Field            | Type                         | Notes                              |
| ---------------- | ---------------------------- | ---------------------------------- |
| customer         | ForeignKey → CustomerProfile |                                    |
| staff            | ForeignKey → StaffProfile    | Optional: auto-assign or manual    |
| service          | ForeignKey → Service         |                                    |
| appointment_date | DateField                    |                                    |
| start_time       | TimeField                    |                                    |
| end_time         | TimeField                    | Can be auto-calculated             |
| status           | CharField                    | e.g., Booked, Completed, Cancelled |
| notes            | TextField                    | Optional                           |
| created_at       | DateTimeField                | Auto-add                           |

---

### 6. **TimeSlot** *(Optional/Advanced)*

Useful if you want to pre-generate slots or check for slot conflicts.

| Field        | Type                      | Notes      |
| ------------ | ------------------------- | ---------- |
| staff        | ForeignKey → StaffProfile |            |
| date         | DateField                 |            |
| start_time   | TimeField                 |            |
| is_available | BooleanField              | True/False |

---

### 7. **Payment**

| Field          | Type                        | Notes                    |
| -------------- | --------------------------- | ------------------------ |
| appointment    | OneToOneField → Appointment |                          |
| amount         | DecimalField                |                          |
| method         | CharField                   | e.g., Cash, Card, Online |
| status         | CharField                   | Paid, Unpaid, Refunded   |
| transaction_id | CharField                   | Optional                 |
| payment_date   | DateTimeField               | Auto on payment          |

---

### 8. **WorkingHours**

Each staff can have a weekly schedule.

| Field       | Type                         | Notes                  |
| ----------- | ---------------------------- | ---------------------- |
| staff       | OneToOneField → StaffProfile |                        |
| day_of_week | IntegerField                 | 0=Monday, 6=Sunday     |
| start_time  | TimeField                    | e.g., 09:00            |
| end_time    | TimeField                    | e.g., 18:00            |
| is_off      | BooleanField                 | True if it's a holiday |

> You may need multiple rows per staff per week — e.g., one per day.

---

### 9. **SalonSettings** *(Optional)*

For storing global config like business hours, buffer time, etc.

| Field | Type      | Notes                       |
| ----- | --------- | --------------------------- |
| key   | CharField | e.g., “buffer_time_minutes” |
| value | TextField | JSON or plain text          |

---

## 🔄 Model Relationships Overview

* **User ←→ CustomerProfile or StaffProfile** (1:1)
* **StaffProfile ←→ Service** (M:M)
* **CustomerProfile ←→ Appointment** (1:M)
* **StaffProfile ←→ Appointment** (1:M)
* **Service ←→ Appointment** (1:M)
* **Appointment ←→ Payment** (1:1)
* **WorkingHours ←→ StaffProfile** (1:1 or 1:M)

---

## 📘 Example Use Case: Booking an Appointment

1. **Customer logs in** and selects a service.
2. System shows available time slots based on:

   * Staff working hours
   * Existing appointments
   * Duration of service
3. Customer chooses a slot and confirms booking.
4. Appointment is saved with status = "Booked".
5. Admin/staff gets notified.
6. After the appointment, staff marks it as “Completed”.
7. Payment is recorded.
